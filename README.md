# رفيق — متجر مستلزمات بيطرية (GitHub فقط)

موقع عربي RTL متجاوب مع لوحة إدارة للمنتجات. تُحفظ بيانات المنتجات والصور داخل مستودع GitHub نفسه؛ لا يحتاج المشروع إلى Supabase أو قاعدة بيانات خارجية.

## كيف يعمل؟

- `index.html`: واجهة الزبائن.
- `admin.html`: لوحة إدارة المنتجات.
- `data/products.json`: قاعدة بيانات المنتجات بصيغة JSON.
- `assets/products/`: صور المنتجات التي ترفعينها من لوحة الإدارة.
- `github-config.js`: إعداد اسم حساب GitHub والمستودع والفرع ومسارات الملفات (لا يحتوي أسراراً).
- `app.js`: يقرأ ملف JSON العام ويعرض المنتجات المنشورة.
- `admin.js`: يستخدم GitHub REST API لإضافة/تعديل/حذف المنتجات ورفع الصور.

**مهم:** GitHub Pages خدمة استضافة ثابتة وليست قاعدة بيانات SQL أو خادماً خلفياً. هنا نستخدم ملف JSON كمخزن بيانات، ومجلداً داخل المستودع للصور. كل حفظ ينشئ Commit جديداً في GitHub، وبعدها قد يحتاج GitHub Pages وقتاً قصيراً لنشر التحديث.

## 1) إنشاء المستودع

1. سجّلي الدخول إلى https://github.com/new
2. اسم المستودع المقترح: `rafiq-vet-store`.
3. اختاري **Public** حتى يتمكن GitHub Pages من عرض الموقع مجاناً على الخطة المجانية.
4. لا تختاري إضافة README أو ملفات تلقائية إذا سترفعين ملفات هذا المشروع كاملة.
5. أنشئي المستودع.

## 2) تعديل إعدادات الموقع

افتحي `github-config.js` وعدّلي `owner` إلى اسم حساب GitHub الخاص بك. اتركي `repo` مطابقاً تماماً لاسم المستودع. مثال إذا كان اسم الحساب `zahraa123`:

```js
window.RAFIQ_GITHUB = {
  owner: 'zahraa123',
  repo: 'rafiq-vet-store',
  branch: 'main',
  productsPath: 'data/products.json',
  imageDirectory: 'assets/products'
};
```

لا تضعي أي Token أو كلمة مرور داخل هذا الملف.

## 3) رفع ملفات المشروع

1. افتحي المستودع في GitHub.
2. اختاري **Add file → Upload files**.
3. ارفعي محتويات مجلد المشروع إلى جذر المستودع، بحيث يظهر `index.html` مباشرة في الصفحة الرئيسية للمستودع، وليس داخل مجلد إضافي.
4. تأكدي من رفع المجلدات `data` و`assets/products` والملف `github-config.js`.
5. اضغطي **Commit changes** إلى فرع `main`.

## 4) تفعيل GitHub Pages

1. من المستودع افتحي **Settings → Pages**.
2. تحت **Build and deployment** اختاري **Deploy from a branch**.
3. اختاري Branch: `main` وFolder: `/(root)`.
4. اضغطي **Save** وانتظري اكتمال النشر.
5. رابط الموقع يكون غالباً `https://USERNAME.github.io/rafiq-vet-store/`.
6. رابط لوحة الإدارة: `https://USERNAME.github.io/rafiq-vet-store/admin.html`.

## 5) إنشاء مفتاح إدارة محدود (Fine-grained Personal Access Token)

تحتاج لوحة الإدارة إلى Token حتى تستطيع تعديل محتوى المستودع. المفتاح لا يُحفظ داخل ملفات الموقع؛ تدخلينه في نموذج لوحة الإدارة عند كل جلسة، ويبقى في ذاكرة الصفحة فقط. عند تحديث الصفحة أو تسجيل الخروج يجب إدخاله مجدداً.

1. افتحي صفحة إنشاء Fine-grained token: https://github.com/settings/personal-access-tokens/new
2. Token name: `Rafiq Store Admin`.
3. Expiration: اختاري مدة قصيرة مناسبة مثل 30 أو 90 يوماً، وجدديه عند انتهائها.
4. Resource owner: حساب GitHub الذي يملك المستودع.
5. Repository access: اختاري **Only select repositories** ثم حددي `rafiq-vet-store` فقط.
6. Repository permissions: اجعلي **Contents = Read and write**. اتركي بقية الصلاحيات على No access، وMetadata تبقى Read-only تلقائياً.
7. اضغطي Generate token وانسخيه فوراً إلى مكان آمن خاص بك. لن يعرضه GitHub كاملاً مرة ثانية.

لا تختاري صلاحيات `Actions` أو `Administration` أو `Workflows`؛ لوحة الإدارة لا تحتاجها. لا تستخدمي Classic token واسع الصلاحيات إذا كان Fine-grained متاحاً.

## 6) الدخول وإدارة المنتجات

1. افتحي رابط `/admin.html`.
2. الصقي Fine-grained token في خانة GitHub Token واضغطي دخول.
3. اضغطي **إضافة منتج**.
4. اختاري صورة JPG أو PNG أو WEBP بحد أقصى 5MB، ثم اكتبي الاسم والسعر والقسم والوصف.
5. اضغطي **حفظ المنتج**. سيُرفع الملف إلى `assets/products/` وتُحدّث بياناته في `data/products.json` بعملية Commit.
6. من القائمة يمكنك تعديل المنتج أو إخفاءه/إظهاره أو حذف المنتج.
7. الزبائن يشاهدون المنتجات ذات حالة «إظهار المنتج» فقط. المنتجات غير المتوفرة تبقى ظاهرة لكن لا يمكن إضافتها للسلة.

## 7) الأمان والخصوصية — اقرئي هذا قبل الاستخدام

- المستودع العام يعني أن ملف المنتجات وصور المنتجات عامة ويمكن لأي شخص رؤيتها أو تنزيلها. لا ترفعي صوراً خاصة أو بيانات زبائن أو معلومات طبية شخصية.
- صفحة الإدارة نفسها عامة كرابط، لكنها لا تنفذ عمليات كتابة من دون Token صالح. هذا ليس نظام حسابات مستقل أو مصادقة متعددة المستخدمين؛ حماية الكتابة تعتمد على سرية Token.
- أنشئي Token مخصصاً لهذا المستودع فقط وبصلاحية Contents: Read and write فقط. أي شخص يحصل على هذا Token يستطيع تعديل ملفات المستودع ضمن الصلاحية الممنوحة.
- لا ترسلي Token في محادثة، ولا تضعيه في `github-config.js` أو أي ملف داخل GitHub أو صور/لقطات شاشة. إذا انكشف، ألغيه فوراً من GitHub Settings → Developer settings → Fine-grained tokens.
- لوحة الإدارة لا تحفظ Token في Local Storage أو ملفات تعريف الارتباط؛ يبقى في ذاكرة الصفحة الحالية فقط. سجّلي الخروج عند الانتهاء.
- لا تشاركي رابط الإدارة مع الآخرين باعتباره حماية بحد ذاته؛ الحماية الفعلية هي Token.
- كل تغيير في المنتجات أو الصور ينشئ Commit في المستودع. حذف المنتج يحذف سجله من JSON ويحاول حذف صورته من مجلد الصور. تبقى النسخ القديمة ظاهرة في تاريخ Git حتى لو حُذفت من الفرع الحالي.
- هذا الحل GitHub-only مناسب لمتجر صغير بمديرة واحدة وعدد تعديلات محدود. ليس بديلاً عن قاعدة بيانات معاملات أو نظام مخزون متزامن لعدد كبير من الإداريين. إذا زاد الاستخدام، الأفضل إضافة Backend آمن.

## 8) فحص التشغيل

- افتحي الموقع العام وتأكدي من ظهور حالة «لا توجد منتجات» إذا كان `data/products.json` فارغاً.
- افتحي لوحة الإدارة وأدخلي Token.
- أضيفي منتجاً تجريبياً بصورة وسعر.
- افتحي واجهة المتجر في تبويب جديد وتحققي من ظهوره بعد اكتمال نشر GitHub Pages.
- عدّلي السعر ثم أخفي المنتج وتحققي من اختفائه من واجهة الزبائن.
- جرّبي الحذف على منتج تجريبي فقط.

## ملاحظات المرحلة الحالية

- المنتجات والصور: GitHub فقط.
- الطلبات وإرسال Telegram: لم يتم تفعيلهما بعد؛ سيحتاجان خطوة منفصلة. لا تضعي Telegram Bot Token داخل JavaScript أو ملفات GitHub العامة.
- الأسعار بالدينار العراقي.
